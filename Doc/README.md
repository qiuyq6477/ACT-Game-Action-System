# 文档目录说明

> 状态：规划中 · 2026-10

这里放的是"为什么这么做"的记录，代码本身的"做了什么"看注释和函数名就够了。

## 目录

| 目录 | 放什么 | 生命周期 |
| :--- | :--- | :--- |
| `plan/` | 重构、功能的设计与推进方案 | 实施完成后把状态翻成"已实施"，可复用的规则要沉淀到对应模块的 AGENTS.md |
| `issue/` | 在做别的任务时顺带发现、但不属于该任务的问题 | 修好后删掉文件和本目录索引里的对应行 |
| `bugfix/` | 一次事故的复盘，一个事件一个文件 | 长期保留 |

## 状态用词

每篇文档标题下面第一行就是状态，只有这几种：

- `规划中 · YYYY-MM`：还没动手，方案可能还在改
- `已实施 · YYYY-MM`：代码已经按这份方案落地
- `未处理` / `处理中`：issue 专用
- `已废弃 →  successor 链接`：被别的文档取代了，保留是为了看历史
- `参考资料`：外部知识的摘录，不是本项目的决定
